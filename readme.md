# Formal Proof Verification Workflow: Lean 4 + Overleaf

This repository demonstrates a workflow for integrating formal theorem proving into LaTeX publishing using Overleaf and GitHub Actions.

While Overleaf does not natively compile theorem prover code, Overleaf's **GitHub Sync** feature allows authors to execute Lean 4 verification checks on GitHub runners and pull the resulting proof verification receipts directly back into their LaTeX project.

---

## Conceptual Overview & Goals

When publishing mathematical results, three distinct layers of abstraction work in tandem:

1. **Human-Oriented Proof (`main.tex`):** Provides the intuitive, high-level narrative and LaTeX formulas designed for human readability.


2. **Tactic Script (`gauss.lean`):** A recipe of high-level Lean tactics (`induction`, `simp`, `linarith`) that directs the Lean elaborator on how to synthesize a formal proof.


3. **Elaborated Proof Term & Receipt (`lean_output.txt`):** The formal $\lambda$-calculus term checked by Lean's trusted kernel.



By offloading proof generation to GitHub Actions, authors can ensure their LaTeX paper references a verified, machine-checked artifact without leaving the Overleaf environment.

## Project Structure & Artifacts

| File / Artifact | Purpose |
| --- | --- |
| **`main.tex`** | Primary LaTeX paper presenting the Gauss summation identity. It includes `gauss.lean` and `lean_output.txt` using the `minted` package.
 |
| **`gauss.lean`** | Lean 4 source file defining the recursive function `sum_to` and proving `gauss_sum` using `linarith`.
 |
| **`lakefile.lean`** | Package manifest specifying project configurations and pinned dependencies (e.g., Mathlib at `v4.7.0`).
 |
| **`lean-toolchain`** | Pins the exact Lean 4 version (`leanprover/lean4:v4.7.0`) used across local and CI environments. |
| **`lake-manifest.json`** | Auto-generated lockfile locking exact dependency commit hashes for build reproducibility. |
| **`lean_output.txt`** | The execution log generated by running `lake env lean gauss.lean` in CI and committed back to Git.
 |
| **`.github/workflows/init_lean.yml`** | A one-time bootstrap workflow that installs `elan`, runs `lake update`, and generates the initial `lake-manifest.json`. |
| **`.github/workflows/lean_action.yml`** | The production workflow that runs `leanprover/lean-action@v1` on demand to re-verify proofs and commit updated receipts.
 |

## Toolchain Stack

* **Elan:** Lean's version manager (similar to `rustup`). Reads `lean-toolchain` and provisions the correct compiler release.
* **Lake:** Lean 4's build system and package manager. Reads `lakefile.lean` and resolves external libraries.


* **Lean 4 Engine:** Comprises the *Elaborator* (which expands tactics in `gauss.lean`) and the *Trusted Kernel* (which validates the synthesized proof terms).


* **Mathlib4:** The formal mathematics library providing tactical automation such as `linarith`.


* **`leanprover/lean-action@v1`:** Official GitHub Action that handles environment setup, caching, and project execution.



---

## How the Workflow Operates

1. **Write & Edit:** Authors edit `main.tex` and `gauss.lean` directly in Overleaf or via local Git.


2. **Trigger Verification:** Pushing changes to GitHub triggers `.github/workflows/lean_action.yml`.


3. **Execute & Commit:** GitHub Actions executes Lean, captures `#print gauss_sum` or `#check gauss_sum` output into `lean_output.txt`, and commits the receipt back to the repository.


4. **Sync Back:** In Overleaf, click **Menu $\rightarrow$ GitHub $\rightarrow$ Pull changes into Overleaf** to fetch the updated `lean_output.txt`, which immediately renders in the PDF compilation.
